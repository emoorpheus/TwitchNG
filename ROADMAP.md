## К пункту 9: форк или отдельный проект

Рекомендация: **отдельный репозиторий (hard fork) с сохранённой историей и явным указанием авторов**, а не кнопка Fork на GitHub.

- Почему не кнопка Fork: форк на GitHub помечается «forked from», хуже находится в поиске, в нём по умолчанию выключены issues. По смыслу Twitch NG уже отдельное приложение: свой id `com.twitchng.tv`, своя линия версий, свой движок, бренд и сборка.
- Как сделать: клонировать SmartTwitchWebOSTV с историей, залить в новый репозиторий `twitch-ng` (или похожий), добавить upstream как remote для подтягивания изменений, положить сверху кит (движок, `brand/`, `build/`, тесты).
- Обязательно: GPL-3.0 (`LICENSE`), копирайты fgl27 и TBSniller в README и About (уже есть), пометка «modified version», ссылка на исходники (`--source-url`).
- Релизы: GitHub Releases с IPK, sha256 и тегом исходников; pre-release, пока не закрыта приёмка на ТВ.
- Если хочется вернуть что-то в исходные проекты (например, исправления моста), это отдельные PR в их репозитории, независимо от выбора.
